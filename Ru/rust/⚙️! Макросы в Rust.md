### 1. Что такое макросы и зачем они нужны?

Макросы - это метапрограммирование (код, который пишет код).

- **Главное отличие от функций:** Функции работают со _значениями_ во время выполнения программы (runtime). Макросы работают с _синтаксическим деревом (AST)_ во время сборки (compile time).
    
- **Пример с `println!`:** Обычная функция в Rust не может принимать переменное количество аргументов разного типа. Макрос `println!` может:
    
    
    
    ```Rust
    println!("Привет"); // 1 аргумент
    println!("Число: {}, текст: {}", 10, "abc"); // 3 аргумента разного типа!
    ```
    

### 2. Зачем нужен `!` (восклицательный знак)?

- Сигнализирует компилятору и программисту: «Это не стандартный вызов функции! Здесь происходит генерация кода».
    
- Это позволяет компилятору проверять аргументы до запуска программы. Например, если в `println!("{}", a, b)` ты передашь 2 переменные, а скобку `{}` укажешь одну, **Rust выдаст ошибку во время сборки**, а не упадет в рантайме!
    

### 3. Две основные категории макросов в Rust

**А. Декларативные макросы (`macro_rules!`)**

- Самый распространенный вид (именно так сделаны `vec!`, `println!`, `format!`).
    
- Работают по принципу **Pattern Matching** (сопоставления с шаблоном): подставляют код в зависимости от того, что ты передал.
    
- Пример простейшего макроса:
    
    
    
    ```Rust
    macro_rules! say_hello {
        () => {
            println!("Hello!");
        };
    }
    
    fn main() {
        say_hello!(); // Развернется в println!("Hello!");
    }
    ```
    

**Б. Процедурные макросы (Procedural Macros)** Принимают код на Rust как поток токенов, модифицируют его и возвращают новый код. Делятся на 3 типа:

1. **Derive-макросы (`#[derive(...)]`):** Автоматически генерируют реализацию трейтов для структур.
    
    
    
    ```Rust
    #[derive(Debug, Clone)] // Вызывает макросы для генерации кода отладки и клонирования
    struct User { name: String }
    ```
    
2. **Атрибутные макросы (`#[tokio::main]`, `#[get("/")]`):** Навешиваются на функции или структуры и полностью переписывают их внутренности.
    
3. **Функционально-подобные макросы:** Вызываются как `custom_macro!(...)`, но обрабатывают содержимое сложной логикой (например, `sqlx::query!`, который проверяет SQL-запросы прямо в БД во время компиляции).

### 4. Короче

Короче, макрос это штука которая вызывает код, и делает его, типо тебе надо перебросить переменную в функцию ты делаешь шаблонный макрос, потом его вызываешь кидаешь параметры и всё, короче это заготовка

### 5. Плюсы и минусы макросов

- **Плюсы:**
    
    - Избавляют от написания пачек шаблонного кода (boilerplate).
        
    - Безопасность: проверки происходят на этапе компиляции.
        
    - Позволяют делать удобные API (как утилка `vec![1, 2, 3]`).
        
- **Минусы:**
    
    - Увеличивают время компиляции проекта.
        
    - Разворачиваемый код сложно отлаживать и читать, если макрос перегружен логикой.
