	В отличие от C# (Unity) или JS, где за памятью следит ленивый Мусорщик (Garbage Collector), в Rust памятью управляешь **ТЫ** через железный свод правил. И логика тут один в один как во времена древнего Рима.

## 👑 1. Правило Владения (Ownership): Один Раб - Один Хозяин

В Rust данные в памяти (например, тяжелая строка `String`) - это **«раб»**. А переменная - это его **«официальный владелец»**.

> **ГЛАВНЫЙ ЗАКОН РАСТА:** У одного «раба» в один момент времени может быть **только один** хозяин. Никакого совладения!

### 🚚 Передача владения насовсем (`Move`)

Если ты передаешь переменную в другую функцию без всяких знаков, ты просто переписываешь документы на владение.



```Rust
fn main() {
    let s1 = String::from("Раб Памяти"); // s1 - первый хозяин
    
    shvyrnut_v_metod(s1); // ПЕРЕДАЛИ документы! (Move)
    
    // println!("{s1}"); // ОШИБКА! s1 больше не хозяин, у неё нет прав на эти данные!
}

fn shvyrnut_v_metod(s2: String) {
    // Теперь s2 - полноправный и единственный хозяин "Раба Памяти"
    println!("{s2}"); 
} // Функция закончилась. s2 умирает, а вместе с ней ОЧИЩАЕТСЯ и память!
```

## 🤝 2. Заимствование (Borrowing): Дать кенту «погонять»

Чтобы переменная не умирала при передаче в методы, ты используешь **Заимствование**. Ты не отдаешь документы на раба, ты просто ставишь знак амперсанда **`&`**. Это значит: _«На, кент, возьми моего раба, пускай сделает работу, но хозяином остаюсь я»_.



```Rust
fn main() {
    let s1 = String::from("Раб Памяти");

    dat_pogonat_kentu(&s1); // Передали ССЫЛКУ (&). Документы остались у s1!
    eshe_один_метод(&s1);   // Без проблем даем погонять второму другу!

    println!("{s1} всё еще служит мне в main!"); // РАБОТАЕТ! Переменная жива!
}

fn dat_pogonat_kentu(rab: &String) {
    println!("Кент пользуется: {rab}");
} // Функция завершилась. Кент вернул раба хозяину в main. Память НЕ удаляется!
```

## 🎭 3. Два вида ссылок (Как правильно давать «погонять»)

Тут есть два строгих правила, чтобы кенты не подрались и не испортили тебе данные:

### 👁️ Вариант А: Ссылка для чтения (`&s`) - «Только посмотреть»

Ты можешь дать ссылку «только посмотреть» **хоть 100 кентам одновременно**. Они могут читать данные, но менять их не имеют права.



```Rust
let r1 = &s1; // Ок
let r2 = &s1; // Ок (все просто смотрят)
```

### 🪓 Вариант Б: Изменяемая ссылка (`&mut s`) - «Дать поработать / изменить»

Если кент хочет изменить данные (например, дописать текст в строку), ты даешь изменяемую ссылку `&mut`.

> **НО:** Дать её можно **только ОДНОМУ кенту в один момент времени**. Пока один работает с топором (`&mut`), никто другой даже подсматривать (`&`) не имеет права, чтобы не случилось багов.



```Rust
fn main() {
    let mut s = String::from("Меч");

    tochit_mech(&mut s); // Передали изменяемую ссылку

    println!("Теперь у нас: {s}"); // Выведет: "Меч заточен!"
}

fn tochit_mech(item: &mut String) {
    item.push_str(" заточен!"); // Изменили данные внутри чужой переменной!
}
```

## 🐑 4. Клонирование (`.clone()`): Сделать точную копию

Если тебе кровь из носу нужно и самому раба оставить, и другу отдать **собственного** раба, ты делаешь клонирование. В памяти создается дубликат. Это дороже по ресурсам, но иногда необходимо.



```Rust
fn main() {
    let s1 = String::from("Граната");
    let s2 = s1.clone(); // Создали второго ТОЧНО ТАКОГО ЖЕ раба в памяти

    // Теперь у s1 свой раб, у s2 - свой. Никто ни от кого не зависит!
    println!("{s1} и {s2} существуют отдельно!");
}
```

### 🧠 Короткая шпаргалка:

1. Передал как есть (`s`) - **отдал документы насовсем**, переменная в `main` умерла.
    
2. Передал с амперсандом (`&s`) - **дал кенту погонять**, переменная жива.
    
3. Передал с мутабельным амперсандом (`&mut s`) - **дал кенту переписать данные**, но кент в этот момент должен быть только ОДИН.
    
4. Вызвал `.clone()` - **создал дубликат в памяти**.
