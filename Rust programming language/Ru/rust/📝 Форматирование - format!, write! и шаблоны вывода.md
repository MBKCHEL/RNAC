### 📝 `format!` и `write!`: собрать текст из кусочков

> 📚 **Если не знаешь, что такое макросы и зачем в конце `!`, посмотри в файле:** [[⚙️! Макросы в Rust|Нажимай!]]

#### ❓ 1. Какую задачу решают эти макросы

Очень часто нужно собрать **одну строку из нескольких кусочков**: из готового текста и значений переменных. Например, из слова «Привет», имени и возраста получить «Привет, Спартак! Тебе 30 лет.»

Оба макроса берут **шаблон** (текст с «дырками») и **данные** (то, что вставить в дырки). Различие только в том, **куда** попадает готовый текст:

|Макрос|Куда попадает текст|Что возвращает|
|---|---|---|
|`format!`|Создаётся **новая** строка|Готовую `String`|
|`write!`|**Дописывается** в уже существующее место (строка, файл, буфер)|`Result`: получилось записать или нет|

---

#### 💻 2. `format!`: собрать новую строку

```Rust
fn main() {
    let name = "Спартак";
    let age = 30;

    let text = format!("Привет, {name}! Тебе {age} лет.");

    println!("{text}"); // Привет, Спартак! Тебе 30 лет.
}
```

##### 🔍 Разбор по кусочкам

- **`{name}` и `{age}`**: это «дырки». Rust ищет переменные с такими же именами и подставляет их значения. Переменные должны существовать **до** вызова `format!`.
- **`let text = format!(...)`**: макрос **возвращает** готовую `String`. Сам он ничего на экран не выводит, а только собирает текст.

##### 🔢 Три способа заполнить дырки

**По имени переменной** (показан выше): `{name}`.

**По порядку.** Дырки оставляешь пустыми, а значения пишешь **после шаблона через запятую**:

```Rust
fn main() {
    let a = 5;
    let b = 7;

    let text = format!("{} + {} = {}", a, b, a + b);

    println!("{text}"); // 5 + 7 = 12
}
```

Первая дырка берёт первое значение, вторая берёт второе, третья берёт третье. Если дырок три, а значений два, получишь ошибку **при компиляции**, а не во время работы программы.

**По номеру или по своему имени.** Это нужно, когда одно значение надо вставить несколько раз или хочется понятных названий:

```Rust
fn main() {
    // По номеру: {0} это первое значение, {1} второе
    let a = format!("{0} против {1}, а {1} против {0}", "Гай", "Марк");

    // По своему имени: имя = значение после запятой
    let b = format!("{hero} победил {enemy}", hero = "Гай", enemy = "Марк");

    println!("{a}");
    println!("{b}");
}
```

> ⚠️ **ЛОВУШКА:** Внутри самих `{}` можно писать **только имя**. Запись `format!("{a + b}")` не скомпилируется. Выражение (`a + b`) передают после запятой или считают заранее в отдельную переменную.

##### 📦 `format!` не забирает переменные

Помнишь про владение? `format!` только **смотрит** на твои переменные, как через `&`. Поэтому после вызова они остаются живыми:

```Rust
fn main() {
    let name = String::from("Спартак");

    let text = format!("Привет, {name}!");

    println!("{name}"); // РАБОТАЕТ! name не потерялась
    println!("{text}");
}
```

##### 🧰 Что делать с результатом

Результат это обычная `String`, значит, её можно использовать как любую строку.

**Вернуть из функции:**

```Rust
fn privetstvie(name: &str) -> String {
    format!("Привет, {name}!") // без точки с запятой: это значение, которое функция возвращает
}

fn main() {
    let text = privetstvie("Гай");
    println!("{text}"); // Привет, Гай!
}
```

**Дописать к другой строке:**

```Rust
fn main() {
    let mut message = String::from("Результат: ");

    let number = format!("{}", 42);
    message.push_str(&number);

    println!("{message}"); // Результат: 42
}
```

**Передать в функцию:**

```Rust
fn shout(text: &str) {
    println!("{text}!!!");
}

fn main() {
    let text = format!("Мне {} лет", 30);
    shout(&text); // передаём ссылку, text остаётся у нас
}
```

##### 🆚 Зачем `format!`, если есть `+`

```Rust
fn main() {
    let name = "Спартак";
    let age = 30;

    // Через format!: коротко и читаемо
    let text = format!("Привет, {name}! Тебе {age} лет.");

    // Через +: длиннее, и число надо вручную превращать в строку
    let text2 = String::from("Привет, ") + name + "! Тебе " + &age.to_string() + " лет.";

    println!("{text}");
    println!("{text2}");
}
```

Результат одинаковый, но `format!` делает всё за тебя: и числа превращает в текст, и читается как готовое предложение.

#### 🎛️ 3. Шаблон: тут `format!` показывает мощь

До сих пор в дырках стояло только имя. Но после имени можно поставить **двоеточие** и написать **правила оформления**: как показать значение, какой ширины, с каким выравниванием. Всё это работает одинаково и в `format!`, и в `write!`, и в `println!`.

Общая форма дырки:

```
{ имя : правила }
```

##### 👁️ 3.1. `{}` и `{:?}`: два способа показать значение

У каждого значения может быть два вида: **для людей** и **для программиста**.

- **`{}`** (Display): красивый вид для людей. Есть не у всего.
- **`{:?}`** (Debug): отладочный вид «как оно устроено внутри». Есть почти у всего.
- **`{:#?}`**: то же, что `{:?}`, но с переносами строк и отступами (удобно для больших данных).

```Rust
fn main() {
    let numbers = vec![1, 2, 3];
    let maybe = Some(5);
    let word = "hi";

    println!("{numbers:?}"); // [1, 2, 3]
    println!("{maybe:?}");   // Some(5)
    println!("{word}");      // hi
    println!("{word:?}");    // "hi"  (Debug показывает кавычки)

    // println!("{numbers}"); // ОШИБКА! У Vec нет вида «для людей»
}
```

Если компилятор пишет, что тип «doesn’t implement `std::fmt::Display`», значит, нужно использовать `{:?}` (или написать свой Display, об этом в разделе 4).

Для **своей структуры** Debug получают одной строчкой `#[derive(Debug)]` над ней:

```Rust
#[derive(Debug)]
struct Warrior {
    name: String,
    hp: u32,
}

fn main() {
    let w = Warrior { name: String::from("Спартак"), hp: 100 };

    println!("{w:?}");
    // Warrior { name: "Спартак", hp: 100 }

    println!("{w:#?}");
    // Warrior {
    //     name: "Спартак",
    //     hp: 100,
    // }
}
```

##### 📐 3.2. Полная формула правил

Правила идут **строго в таком порядке** (каждое можно пропустить):

```
{ : [заполнитель][выравнивание][знак][#][0][ширина][.точность][тип] }
```

|Часть|Что делает|Пример|
|---|---|---|
|заполнитель|Символ для заполнения пустого места (по умолчанию пробел)|`*`|
|выравнивание|`<` влево, `^` по центру, `>` вправо|`>`|
|знак|`+` показывать знак у чисел|`+`|
|`#`|«Красивая» форма (префикс `0x`, или `{:#?}`)|`#`|
|`0`|Дополнить число нулями слева|`0`|
|ширина|Минимальная ширина в символах|`10`|
|`.точность`|Знаков после запятой (у дробных) или максимум символов (у строк)|`.2`|
|тип|Как показать число: `x`, `b`, `e` и т.д.|`x`|

Не пугайся, сейчас разберём по частям.

##### ↔️ 3.3. Ширина и выравнивание

Ширина это **минимальное** количество символов. Если текст короче, остальное заполняется пробелами. Если длиннее, он не обрезается.

```Rust
fn main() {
    println!("[{:8}]", "Меч");   // [Меч     ]  строки по умолчанию прижимаются влево
    println!("[{:8}]", 42);      // [      42]  числа по умолчанию прижимаются вправо

    println!("[{:<8}]", "Меч");  // [Меч     ]  влево
    println!("[{:>8}]", "Меч");  // [     Меч]  вправо
    println!("[{:^8}]", "Меч");  // [  Меч   ]  по центру
}
```

Хочешь заполнять не пробелами, а другим символом? Поставь его **перед** выравниванием:

```Rust
fn main() {
    println!("{:*^20}", "Меч");  // ********Меч*********
    println!("{:-<15}", "Щит");  // Щит------------
    println!("{:.>15}", "Шлем"); // ...........Шлем
}
```

Ширина считается в **символах**, а не в байтах, поэтому с кириллицей всё выравнивается нормально.

##### 🔢 3.4. Точность, знак и нули

```Rust
fn main() {
    let pi = 3.14159265;

    println!("{pi:.2}");    // 3.14      два знака после запятой
    println!("{pi:.0}");    // 3         ноль знаков
    println!("{pi:8.3}");   //    3.142  ширина 8, три знака после запятой
    println!("{pi:08.3}");  // 0003.142  то же, но с нулями слева

    println!("{:05}", 42);  // 00042     дополнить нулями до ширины 5
    println!("{:+}", 7);    // +7        показать знак
    println!("{:+}", -7);   // -7

    println!("{:.3}", "Привет"); // При  у строк точность это максимум символов
}
```

##### 🧮 3.5. Системы счисления

Для программиста на низком уровне это очень полезно:

```Rust
fn main() {
    let n = 255;

    println!("{n}");      // 255         обычное (десятичное)
    println!("{n:x}");    // ff          шестнадцатеричное, строчные буквы
    println!("{n:X}");    // FF          шестнадцатеричное, заглавные
    println!("{n:#x}");   // 0xff        с префиксом 0x
    println!("{n:b}");    // 11111111    двоичное
    println!("{n:#b}");   // 0b11111111  двоичное с префиксом
    println!("{n:o}");    // 377         восьмеричное

    println!("{:08b}", 5);   // 00000101    двоичное, дополнено нулями до 8 цифр
    println!("{:#010b}", 5); // 0b00000101  с префиксом (ширина 10 включает «0b»)
    println!("{:e}", 1500.0); // 1.5e3      научная запись
}
```

Запись `{:08b}` читается так: «нулями (`0`), до ширины 8 (`8`), в двоичном виде (`b`)».

##### 🪄 3.6. Ширина и точность из переменной

Если ширину нельзя вписать числом заранее, используй имя переменной с `$` на конце:

```Rust
fn main() {
    let width = 12;
    let prec = 3;

    println!("[{:>width$.prec$}]", 3.14159265);
    // [       3.142]
}
```

`width$` значит «ширину возьми из переменной `width`», а `prec$` значит «точность возьми из переменной `prec`».

##### 🚪 3.7. Как вывести сами фигурные скобки

Раз `{` и `}` заняты под дырки, чтобы показать сами скобки, их **удваивают**:

```Rust
fn main() {
    let name = "Гай";
    let text = format!("{{name}} = {name}");

    println!("{text}"); // {name} = Гай
}
```

##### 🧾 3.8. Собираем всё вместе: ровная таблица

```Rust
fn main() {
    let items = [("Меч", 150.5), ("Щит", 80.0), ("Шлем", 45.25)];

    println!("{:<10}|{:>8}", "Товар", "Цена");
    println!("{:-<10}+{:->8}", "", "");

    for (name, price) in items {
        println!("{name:<10}|{price:>8.2}");
    }
}
```

Вывод:

```
Товар     |    Цена
----------+--------
Меч       |  150.50
Щит       |   80.00
Шлем      |   45.25
```

Название прижато влево и занимает 10 символов, цена прижата вправо, занимает 8 и показывает два знака после запятой.

#### 🖊️ 4. `write!`: дописать в уже существующее место

`format!` каждый раз создаёт **новую** строку. А `write!` пишет туда, **куда ты укажешь**: в уже существующую `String`, в файл, в консоль. Шаблон у него **точно такой же**, как у `format!`, только перед шаблоном добавляется ещё один аргумент: **куда писать**.

```
format!( шаблон, данные )
write!( куда_писать, шаблон, данные )
```

Есть и версия `writeln!`: то же самое, но в конце текста добавляет перевод строки.

##### 📜 4.1. Запись в `String`

```Rust
use std::fmt::Write; // ВАЖНО! Без этой строки write! для String не заработает

fn main() {
    let mut text = String::new(); // пустая строка, mut потому что будем дописывать

    write!(text, "Привет, {}!", "Гай").unwrap();
    writeln!(text, " Тебе {} лет.", 30).unwrap();
    write!(text, "Конец.").unwrap();

    println!("{text}");
}
```

Вывод:

```
Привет, Гай! Тебе 30 лет.
Конец.
```

##### 🔍 Разбор по кусочкам

- **`use std::fmt::Write;`**: это трейт, как `RngExt` в конспекте про `rand`. Без импорта Rust скажет, что у `String` нет метода `write_fmt`. Если видишь такую ошибку, ты просто забыл эту строку.
- **`let mut text`**: `mut` обязателен, потому что мы **изменяем** строку, дописывая в неё.
- **`write!(text, ...)`**: первым аргументом идёт **куда писать**. Ссылку (`&mut text`) писать не нужно, макрос сам её берёт.
- **`writeln!`**: сам добавил перенос строки после текста. Поэтому «Конец.» оказалась на новой строке.
- **`.unwrap()`**: разбор в следующем пункте.

##### ❓ 4.2. Что за `.unwrap()` и почему `write!` возвращает `Result`

`format!` просто возвращает строку, и ничего не может пойти не так. А `write!` пишет в чужое место, и там **теоретически** может случиться сбой (например, в файле закончилось место на диске). Поэтому он возвращает **`Result`**: «получилось или нет».

Если игнорировать результат, компилятор выдаст предупреждение `unused Result that must be used`. Есть три способа его обработать:

- **`.unwrap()`**: «если ошибка, то аварийно остановить программу». Для записи в `String` это безопасно, потому что запись в строку в памяти не ломается.
- **`?`**: «если ошибка, то сразу выйти из функции и вернуть эту ошибку наверх». Работает только в функции, которая сама возвращает `Result`. Именно так обычно пишут для файлов.
- **`let _ = write!(...);`**: «мне всё равно, получилось или нет».
- *Подробнее в файле*: [[⚠️Обработка ошибок в Rust|Нажимай!]]

##### 🔁 4.3. Зачем писать в `String`, если есть `format!`

Главная причина **цикл**. Допустим, нужно собрать длинный текст из многих кусочков.

```Rust
use std::fmt::Write;

fn main() {
    let mut report = String::new();

    for i in 1..=3 {
        writeln!(report, "Строка номер {i}").unwrap();
    }

    print!("{report}"); // print! это println! без лишнего перевода строки
}
```

Вывод:

```
Строка номер 1
Строка номер 2
Строка номер 3
```

Если бы мы собирали такой текст через `format!`, пришлось бы на каждом шаге создавать новую временную строку, а потом приклеивать её к основной. А `write!` дописывает **прямо в нужную строку**, без лишних копий. Это и короче, и быстрее.

##### 📁 4.4. Запись в файл и в консоль

Тут нужен **другой** трейт, из другого места:

```Rust
use std::fs::File;
use std::io::Write; // для файлов и консоли это std::io::Write (не fmt!)

fn main() -> std::io::Result<()> {
    let mut file = File::create("hello.txt")?;

    writeln!(file, "Привет, {}!", "файл")?;
    writeln!(file, "Мне {} лет.", 30)?;

    Ok(())
}
```

После запуска появится файл `hello.txt` с двумя строками.

##### 🔍 Разбор по кусочкам

- **`use std::io::Write;`**: трейт для записи во внешний мир (файлы, консоль, сеть). Он **не** тот же самый, что `std::fmt::Write` для строк.
- **`fn main() -> std::io::Result<()>`**: мы разрешаем `main` возвращать результат. Это нужно, чтобы использовать `?`.
- **`File::create("hello.txt")?`**: создаём файл. `?` значит «если не вышло создать (например, нет прав), то выйти из `main` с ошибкой».
- **`writeln!(file, ...)?`**: пишем строку в файл и точно так же проверяем результат через `?`.
- **`Ok(())`** в конце: «всё прошло успешно, возвращать нечего». `()` это пустое значение.

То же самое работает для консоли:

```Rust
use std::io::Write;

fn main() -> std::io::Result<()> {
    let mut out = std::io::stdout(); // «куда писать» это стандартный вывод

    writeln!(out, "Привет из stdout, мне {} лет", 30)?;

    Ok(())
}
```

> ⚠️ **ЛОВУШКА:** Оба трейта называются `Write`. Если понадобятся оба в одном файле, будет конфликт имён. Решение: импортировать один из них под другим именем:
```Rust
> use std::fmt::Write as FmtWrite;
> use std::io::Write;
```
> Или, если нужен только для работы метода, можно написать `use std::fmt::Write as _;`.

##### 🏗️ 4.5. Главный сценарий: научить свою структуру выводиться через `{}`

Помнишь, что `{}` работает не у всех типов? У `Vec` его нет. И у твоей структуры тоже не будет, пока ты сам не опишешь, **как её показывать людям**. Именно здесь `write!` нужен чаще всего.

```Rust
use std::fmt;

struct Point {
    x: i32,
    y: i32,
}

impl fmt::Display for Point {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        write!(f, "({}, {})", self.x, self.y)
    }
}

fn main() {
    let p = Point { x: 3, y: 5 };

    println!("Точка: {p}");          // Точка: (3, 5)
    let text = format!("Мы тут: {p}");
    println!("{text}");              // Мы тут: (3, 5)
}
```

##### 🔍 Разбор по кусочкам

- **`impl fmt::Display for Point`**: «я описываю, как `Point` показывать через `{}`». `Display` это тот самый «вид для людей».
- **`fn fmt(&self, f: &mut fmt::Formatter)`**: так называется метод, который Rust вызывает, когда встречает `{}` с твоим типом. `&self` это ссылка на саму точку (помнишь заимствование?). `f` это изменяемая ссылка на **«лист бумаги»**, на котором сейчас собирается текст.
- **`write!(f, "({}, {})", self.x, self.y)`**: пишем на этот лист. Первый аргумент `f`, то есть «куда писать». Остальное это обычный шаблон.
- **Нет точки с запятой в конце**: результат `write!` и есть то, что возвращает функция. Тип `fmt::Result` это тот самый «получилось или нет».

После этого `Point` умеет всё: работает в `println!("{p}")`, в `format!("{p}")` и даже получает метод `p.to_string()` бесплатно.

> ⚠️ **Нюанс:** ширина и выравнивание (`{p:>10}`) для твоего типа **не сработают сами**, пока внутри `fmt` ты просто используешь `write!`. Чтобы они работали, нужно использовать `f.pad(...)`, но это уже тема для продвинутого конспекта.

##### 🤔 4.6. Что когда использовать

- **Нужна новая строка**, и всё: `format!`.
- **Собираешь длинный текст по кускам** (в цикле, в нескольких местах): `write!` или `writeln!` в `String` (`std::fmt::Write`).
- **Пишешь в файл или консоль**: `write!` или `writeln!` (`std::io::Write`).
- **Описываешь, как показывать свою структуру**: `write!(f, ...)` внутри `impl Display`.

#### 🧠 Короткая шпаргалка

**Основа**

1. `format!(шаблон, данные)` возвращает **новую** `String`, на экран ничего не выводит.
2. `write!(куда, шаблон, данные)` **дописывает** в указанное место и возвращает `Result`.
3. `writeln!` это то же, что `write!`, но с переводом строки в конце.
4. Шаблон у `format!`, `write!`, `println!` **одинаковый**.
5. Макросы не забирают переменные, а только смотрят на них, поэтому они остаются живыми.

**Дырки**

6. `{name}` по имени переменной, `{}` по порядку (значения после запятой), `{0}` по номеру, `{x}` с `x = значение` после запятой.
7. Внутри `{}` только имя, выражения (`a + b`) нельзя.
8. Сами скобки выводятся удвоением: `{{` и `}}`.

**Правила оформления** `{:[заполнитель][выравнивание][знак][#][0][ширина][.точность][тип]}`

9. `{}` для людей, `{:?}` отладочный вид, `{:#?}` отладочный с отступами. Свой Debug даёт `#[derive(Debug)]`.
10. Ширина: `{:8}`. Выравнивание: `<` влево, `^` центр, `>` вправо. Заполнитель ставится перед ним: `{:*^20}`.
11. Точность: `{:.2}` (два знака после запятой), `{:08.3}` (с нулями слева).
12. Знак: `{:+}`. Нули: `{:05}`.
13. Системы счисления: `x` (hex), `X` (HEX), `b` (двоичное), `o` (восьмеричное), `e` (научная запись). `#` добавляет префикс: `{:#x}` даёт `0xff`.
14. Ширина и точность из переменной: `{:>width$.prec$}`.

**`write!`**

15. В `String` нужен импорт **`use std::fmt::Write;`**, и `mut` у строки.
16. В файл и консоль нужен **`use std::io::Write;`**, это другой трейт.
17. Результат `write!` нельзя игнорировать: `.unwrap()` (для строк безопасно), `?` (в функции, возвращающей `Result`), или `let _ =`.
18. `write!` в цикле лучше, чем склеивать `format!`: не создаются лишние временные строки.
19. Свой `Display`: `impl fmt::Display for Тип`, внутри `write!(f, ...)` **без точки с запятой** в конце.
20. Ошибка про отсутствие метода `write_fmt`? Забыл импортировать `Write`. Ошибка «doesn’t implement `Display`»? Используй `{:?}` или напиши свой `Display`
