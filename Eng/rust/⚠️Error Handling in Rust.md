В Rust нет привычных исключений (`try/catch`). Все ошибки делятся на две категории: **невосстановимые** (паника) и **восстановимые** (`Result`).

### **1. Невосстановимые ошибки: макрос `panic!`**

Макрос `panic!` принудительно останавливает выполнение программы, выводит сообщение об ошибке, очищает стек и завершает процесс. Используется, когда программа попала в невалидное состояние, из которого нельзя продолжать работу.

**Основные варианты вызова:**

- **Прямой вызов макроса:**
    
    
    
    ```Rust
    panic!("Все сгорело!"); // Завершит программу с этим сообщением
    ```
    
- **Автоматическая паника (например, выход за границы массива):**
    
    
    
    ```Rust
    let v = vec![1, 2, 3];
    v[99]; // Вызовет panic! (buffer overflow / out of bounds protection)
    ```
    
- **Распаковка `Option` / `Result` через `.unwrap()` и `.expect()`:**
    
    
    
    ```Rust
    let f = File::open("hello.txt").unwrap(); 
    // Если файла нет -> panic!
    
    let f = File::open("hello.txt").expect("Не удалось открыть файл"); 
    // Если файла нет -> panic! с твоим кастомным текстом (Best Practice)
    ```
    

### **2. Настройка поведения при `panic!`**

По умолчанию при панике Rust делает **unwinding** (разворачивание стека): идет назад по функциям и очищает память. Это можно изменить в `Cargo.toml`:

, 

```TOML
[profile.release]
panic = 'abort' # Немедленный забор процесса (уменьшает размер бинарника)
```

> **Для системщика / OS Dev:** Флаг `RUST_BACKTRACE=1` в терминале выводит полный стек вызовов (backtrace) при панике:
> 
> Bash
> 
> ```
> RUST_BACKTRACE=1 cargo run
> ```

### **3. Восстановимые ошибки: перечисление `Result<T, E>`**

Если ошибка ожидаема (например, файл не найден или сеть отвалилась), используется `Result`:



```Rust
enum Result<T, E> {
    Ok(T),  // Операция прошла успешно, возвращает значение T
    Err(E), // Произошла ошибка, возвращает ошибку E
}
```

### **4. Оператор `?` (Проброс ошибок / Error Propagation)**

Оператор `?` - это короткая запись для передачи ошибки выше по стеку вызовов. Если метод возвращает `Err`, оператор `?` прерывает выполнение функции и сразу возвращает этот `Err`.



```Rust
use std::fs::File;
use std::io::{Self, Read};

fn read_username_from_file() -> Result<String, io::Error> {
    let mut username = String::new();
    
    // Если File::open вернет Err, '?' сразу вернет этот Err из функции
    File::open("hello.txt")?.read_to_string(&mut username)?;
    
    Ok(username)
}
```

### **Короткая шпаргалка: Когда что юзать?**

- **`panic!` / `.expect()`:** При написании примеров, тестов, прототипов или когда состояние программы **абсолютно невалидно** и продолжать работу опасно.
    
- **`Result` / `?`:** В библиотеках, критическом коде и функциях, где вызывающая сторона должна сама решить, как обработать сбой.
