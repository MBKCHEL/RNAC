В Rust всё строится вокруг **Crate** (крайта/пакета) и **Tree of Modules** (дерева модулей). Корнем дерева всегда является файл `src/main.rs` (для бинарников) или `src/lib.rs` (для библиотек).

## 1. Главное правило разделения на файлы

> **В Rust файл сам по себе НЕ становится модулем автоматически.**
> 
> Чтобы файл стал модулем, его **ОБЯЗАТЕЛЬНО** нужно объявить в родительском файле через ключевое слово `mod`.

## 2. Варианты структуры файлов

Представим, что мы хотим вынести логику работы с ЦП в отдельный модуль `cpu`.

### Вариант А: Одиночный файл (для небольших модулей)

1. Создаём файл: `src/cpu.rs`
    
2. В коде `src/cpu.rs`:
    
    
    
    ```Rust
    pub fn print_info() {
        println!("CPU Info");
    }
    ```
    
3. Объявляем его в `src/main.rs`:
    
    
    
    ```Rust
    mod cpu; // Rust ищет либо src/cpu.rs, либо src/cpu/mod.rs
    
    fn main() {
        cpu::print_info();
    }
    ```
    

### Вариант Б: Папка с подмодулями (для сложных компонентов)

Если модуль разрастается (как у тебя с `sysinfo` в SysPrint), его удобнее разбить на папку с подфайлами:

**Структура папок:**



```Plaintext 
src/
├── main.rs
└── sysinfo/
    ├── mod.rs        <-- Главный файл модуля
    ├── cpu.rs        <-- Подмодуль
    └── memory.rs     <-- Подмодуль
```

1. В `src/sysinfo/cpu.rs`:
    
    
    
    ```Rust
    pub fn get_usage() -> f32 { 15.4 }
    ```
    
2. В `src/sysinfo/mod.rs` (объявляем подмодули):
    
    
    
    ```Rust
    pub mod cpu;    // Объявляем sysinfo/cpu.rs
    pub mod memory; // Объявляем sysinfo/memory.rs
    ```
    
3. В `src/main.rs` (подключаем верхнеуровневый модуль):
    
    
    
    ```Rust
    mod sysinfo;
    
    fn main() {
        let usage = sysinfo::cpu::get_usage();
    }
    ```
    

## 3. Публичность (`pub`) и видимость

По умолчанию в Rust **всё приватно** (и функции, и структуры, и модули).

- `pub fn`: делает функцию доступной снаружи модуля.
    
- `pub mod`: делает модуль доступным снаружи родительского модуля.
    
- `pub struct MyStruct`: делает саму структуру публичной, **НО её поля остаются приватными**! Чтобы поля были видны, им тоже нужен `pub`:
    
    
    
    ```Rust
    pub struct Config {
        pub enable_color: bool, // Публичное поле
        secret_key: String,     // Приватное поле
    }
    ```
    

## 4. Сокращение путей: `use` и `pub use` (Реэкспорт)

### Ключевое слово `use`

Чтобы не писать каждый раз длинный путь `crate::sysinfo::cpu::get_usage()`, мы импортируем его:



```Rust
use sysinfo::cpu;

fn main() {
    cpu::get_usage();
}
```

### Пути: `crate::`, `super::`, `self::`

- `crate::` - путь от корня проекта (`src/main.rs`).
    
- `super::` - путь от родительского модуля (как `..` в терминале).
    
- `self::` - путь от текущего модуля.
    

### `pub use` (Реэкспорт / Re-exporting)

Очень мощная фича для удобства пользователей твоей библиотеки/модуля. Позволяет сделать структуру внутренней папки скрытой, вытащив нужные функции наверх.

В `src/sysinfo/mod.rs`:



```Rust
mod cpu; // сам файл приватный

pub use cpu::get_usage; // вытаскиваем функцию напрямую в sysinfo
```

Теперь в `main.rs` можно вызывать просто `sysinfo::get_usage()`, не зная, в каком именно внутреннем файле она лежит!

## Шпаргалка по чеклисту:

1. Создал файл `src/something.rs` $\rightarrow$ не забудь прописать `mod something;` в `main.rs`.
    
2. Не видишь функцию из другого файла $\rightarrow$ проверь, стоит ли `pub` перед `fn` и перед `mod`.
    
3. Хочешь красивый чистый `main.rs` $\rightarrow$ используй `use crate::module::submodule;`.
